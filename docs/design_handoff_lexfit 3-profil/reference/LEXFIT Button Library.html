Eight heights and twelve radii is not a system.

Every wireframe in this set invented its buttons locally. Auditing them turns up eight distinct heights between 26 and 52px and twelve different corner radii — none of which is wrong on its own, and all of which together mean nothing can be reused. This page reduces them to a four-step ladder, four levels of emphasis, and the repo's own radius tokens. Every number below traces to a measurement or a standard, not to taste.

WCAG 2.2 · 2.5.8 AA — 24px floor WCAG · 2.5.5 AAA — 44px Apple · 44pt · Material · 48dp RULE 05 · one loud action per screen

The 26px save button

The most-used control on the busiest screen, and it is 18px under Apple's floor. On a phone it is a mis-tap generator.

Not a redesign

Nothing below changes how a button looks. It changes how many kinds there are — from roughly fifteen to eight.

Align to the repo

Radius comes from lexfit-tokens.css, not from this document. The design system is downstream of the code that already exists.

BT2

The size ladder — four steps

Why 40 is the default

Comfortable with a mouse, and it promotes cleanly to 48 on touch. 44 as a desktop default reads oversized next to 34px chips and a 34px search field.

XS carries a condition

28px is legal under WCAG 2.5.8 only via the spacing exception — 24px of clear offset to every neighbour. If it cannot have that room, use S.

Padding is derived

Roughly height × 0.45. It means a new size cannot be invented with the wrong proportions, and buttons look related without anyone measuring.

The 43% number

NN/g: users over 65 are 43% slower at the same tasks. For a 35+ audience skewing older, generous targets are not a compliance box — they are the product working.

BT3

Four levels of emphasis

Fill for the one action that matters, outline for real alternatives, text for navigation, red only for destruction. RULE 05 is the constraint that makes this work: exactly one filled button in the viewport at a time. A second one halves the value of the first.

01 · ElsődlegesEdzés indítása

Ink fill. One per viewport. The thing you came to do.

02 · MásodlagosMit fogok ma csinálni?

Outline. A real alternative, not a lesser one. Any number.

03 · HalványÖsszes megtekintése

Text only. Navigation and dismissal. Never the main action.

04 · RombolóElőfizetés lemondása

Red text. Filled red only inside a confirm dialog.

Sorrend és térköz
ElsődlegesMásodlagos← 12px köz

Primary on the left, secondary right, in a flex row with gap: 12px — never margins, so the pair survives reordering. Minimum 8px between any two targets; 12px is the default. Icon-only buttons under 44px need 24px offset to satisfy WCAG 2.5.8.

Fill is a budget

There is exactly one filled button per screen. Treat it as scarce — the hero's "Edzés indítása" spends it on Kezdőlap, so nothing else on that page may be filled.

Secondary is not weaker

Outline means a different thing, not a less important thing. "Mit fogok ma csinálni?" is a legitimate destination, just not the default one.

Red is rationed harder

Text-red for the affordance, filled-red only for the final confirm. A filled red button in a settings list is a trap for a fast-moving thumb.

Gap, not margin

Button rows use flex gap. Per-element margins break the moment someone reorders or removes one.

Five values total, three of them already tokenised as --r-sm / --r-md / --r-lg. A button is always 8 unless it is a pill or a circle — there is no in-between case.

Icon left, almost always

It is read before the word, so it should preview the action. Right-side icons mean direction only — a right chevron on a save button is nonsense.

Icon-only is a last resort

NN/g: icons need labels, and this audience skews older. Only +, ✓, ▶, × and ⋯ are safe unlabelled.

One radius for buttons

8px, from the repo. No exceptions except pills and circles — and both are visibly different shapes, not near-misses.

BT5

Icon buttons and the hit area

The card's save + is 26px today. The rule that fixes it without redrawing anything: the visual size and the target size are different numbers. Padding counts toward the target, so a 14px glyph in a 44px flex box is compliant and still looks small.

/* visual size stays 26px; the target reaches 44 */
.card-save{
  /* hit area */
  min-width: 44px; min-height: 44px;
  display: inline-flex; align-items: center; justify-content: center;
  background: none; border: none; padding: 0;
  /* pull the extra box out of the layout so nothing shifts */
  margin: -9px;
}
.card-save > span{ /* the visible 26px circle */
  width: 26px; height: 26px; border-radius: 50%;
  border: 1px solid var(--line); background: var(--surface);
}
Padding counts

WCAG measures the target, not the drawn shape. A small glyph inside a large flex box is fully compliant — and it is invisible to the design.

Negative margin absorbs it

margin: -9px pulls the oversized box back out of the flow, so nothing in the card moves.

Nested buttons need care

The save + sits inside a card that is itself a button. stopPropagation on click, and it must be reachable by keyboard in its own right.

Kivétel 01 · a lejátszó fő gombja
10 mp

56px, off the ladder, on purpose. It is operated from three metres away, mid-movement, by someone out of breath. The player is the one screen where the distance rule beats the size scale.

Kivétel 02 · a kártya lejátszás-jelzése

38px, and not a button. It is an affordance drawn on the thumbnail — the whole card is the target. It never receives focus separately and it is not in the tab order.

Never resize on hover

A growing button nudges its neighbours and moves the thing the user is aiming at. Colour changes only.

Loading must not resize

Swap the icon for a spinner and keep the label. A button that shrinks to a spinner moves everything after it.

Focus ring is non-negotiable

2px accent at 2px offset, on every level including ghost. Keyboard users are the whole reason it exists.

Two exceptions, both justified

A system with no exceptions is usually wrong. A system with documented exceptions is a system; undocumented ones are drift.

BT8

Rules

B-RULE 01

Four heights. No others.

28 · 34 · 40 · 48 on desktop; everything promotes to a 44px floor below 840px.

EvidenceWCAG 2.5.8 sets 24px as the AA floor, 2.5.5 AAA asks 44; Apple 44pt, Material 48dp.
B-RULE 02

One filled button per viewport.

Outline for alternatives, text for navigation. Fill is a budget, not a style.

EvidenceRULE 05 — Nielsen: users overlook quiet primary CTAs, and three loud ones is the same failure.
B-RULE 03

Padding and icon size derive from height.

Roughly height × 0.45 horizontal, × 0.38 for the icon, 8px gap at every step.

EvidenceDerived values cannot drift; chosen values always do — see the BT1 audit.
B-RULE 04

Buttons are 8px. Pills are 999. Circles are 50%.

Nothing in between. Radius comes from --r-sm in the repo token file.

EvidenceTwelve radii currently in use; no user can distinguish 7 from 8 from 9.
B-RULE 05

The visual size and the hit area are separate numbers.

Small glyph, large flex box, negative margin to absorb it.

EvidenceWCAG measures the target, and padding counts toward it.
B-RULE 06

Icon left unless the meaning is directional.

Icon-only is limited to + ✓ ▶ × ⋯, always with an aria-label.

EvidenceNN/g on icon usability: labels required; F-10 in the original audit.
B-RULE 07

Nothing resizes on hover or while loading.

Colour changes, a 1px press shift, and a spinner in place of the icon. That is the whole vocabulary.

EvidenceA button that grows moves the target the user is already aiming at.
B-RULE 08

Rows use flex gap, minimum 8px.

12px default; 24px offset around any target under 44px.

EvidenceWCAG 2.5.8 spacing exception; gap survives reordering where margins do not.

Amit szándékosan nem csinálunk

✕Új méret egy egyedi helyzetre. If none of the four fits, the layout is wrong, not the ladder.
✕Ikon felirat nélkül a mentés, lejátszás, bezárás és „továbbiak" öt jelén kívül.
✕Kitöltött gomb egy kártyán belül. The card is already the target; a filled button inside it competes with itself.
✕Fókuszgyűrű eltávolítása, soha, semmilyen szinten — a billentyűzetes használat ezen múlik.
✕Árnyék a gombokon. Elevation belongs to cards and sheets; a raised button in a flat system reads as a different era.
✕Tiltott gomb magyarázat nélkül. Say what would enable it, next to it.
Nyitott kérdés

One: whether XS at 28px should exist at all. It only works with the WCAG spacing exception, and the one place it is needed — the card save + — is solved better by the hit-area rule in BT5. Dropping it would leave a three-step ladder, which is simpler. Worth deciding before this reaches code.
